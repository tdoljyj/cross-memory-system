# Evidence to Context binding — local engineering candidate

The existing M1 Evidence ingest stores the supplied original-content SHA256 and size. Existing Record mutation checks that every source_refs Evidence ID belongs to the same owner, persists those exact IDs, and issues the existing Event/Receipt. Existing context search authorizes the current binding and exact context session but omits source_refs and Evidence metadata. This candidate fills that internal read gap without replacing the frozen minimum compiler or changing a public MCP response.

`read-sources.candidate.sql` creates one table-free, private `clued_source_reader` schema and one definer function. Only service_role gets schema USAGE and function EXECUTE; anon/authenticated get neither. No privilege on old clued_private is changed. Its existing resolver/session-bound search determines eligible records first. The adapter checks selected ID/version/scope/content/lifecycle against the current same-owner record, locks that record for share and returns only its linked Evidence ID/hash/size/schema version. It rejects empty, foreign or unavailable references and history selection. It returns no Evidence storage URI, original bytes, session token or account ID.

`compiler-with-sources.mjs` calls that function with a trusted PostgreSQL client and the actual binding/session credentials, invokes the already reviewed compiler, checks each caller-supplied Buffer against the actual stored Evidence SHA256 and size, then includes every source binding in the final text and counts that complete text with the existing bound real tokenizer. Two different Evidence IDs with identical bytes remain distinct. The derived Canonical content hash is never substituted for the original source hash. The caller must acquire those Buffers through its independently authorized original-source channel; this module does not fetch arbitrary URLs or confer access to raw bytes.

Run `node --test call-boundary.test.mjs source-binding-db.test.mjs` in this directory. Final result: 7 PASS, 0 failed/skipped (one pure test plus five PG child tests and their parent). A dedicated real local PostgreSQL instance loads existing migrations, uses the existing anon public ingest/mutation/restore RPCs, then uses service_role only for the new internal read. Synthetic unconfirmed user_explicit mutation is actually rejected with no record; explicit synthetic confirmation creates a note referencing both ingested Evidence IDs. The candidate stage is an in-memory request, not a newly invented persisted candidate registry or a model/human acceptance claim. Read-time full Record/Evidence/Event/Receipt rows remain equal; existing search still updates session last_seen_at.

Actual negative observations cover fabricated tokenizer before SQL, wrong/missing source bytes, wrong Canonical version, unauthorized context, invalid session, absent/unlinked/cross-owner Evidence, live revoked record and revoked binding. Cross-owner malformed links and lifecycle corruption probes are setup changes only in the synthetic database; no production incident is implied. No model or Gold data is used. Test cleanup stops the dedicated PG server and removes only its checked temporary directory.

The first test attempt exposed that existing public ingest grants belong to anon/authenticated rather than service_role. The next exposed that clued_private has no service_role USAGE. The fixture role was corrected, and the new adapter was moved to its isolated table-free schema rather than opening the old private namespace. These failures are retained in CandidateEvidence. The final run follows an added early tokenizer guard; old compiler tests/PG suites were not rerun.

Boundary: LOCAL_ENGINEERING_ONLY / CANDIDATE_NOT_DEPLOYED. The source's stored hash is an ingest assertion; the new observation proves supplied bytes match that assertion, not external origin authenticity, semantic entailment of a record, immutable external storage, timestamp freshness after return or full source-field access policy. Current authorizations are checked at the read, with no cache/fallback. No new Authority, business Canon, Receipt, public wire, GA, formal Slice A result, or Entry claim is created. Production/nonproduction deployment and an accepted host tokenizer, task policy and execution inputs remain separate. The code is a concrete internal adapter candidate; no current Worker route is silently rewired to use it.
