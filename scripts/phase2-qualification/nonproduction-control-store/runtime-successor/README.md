# Same-domain qualification runtime storage candidate

This is a new, uninstalled extension of the existing private clued_control schema. It creates four empty tables, fixed private client functions and an immutable-bytes trigger function. Existing Root tables, functions, rows and grants are unchanged. No new Canon, trust root, management credential, public RPC or issuer is introduced.

The real disposable PostgreSQL run passed 10/10 Node-reported tests (nine checks and their parent), zero skipped, in 2854.2779 ms. It verifies concurrency, exact-byte idempotency, duplicate JSON rejection, Owner-window bounds, separate generation changes/rollback rejection, one-active budget reservation, send-before-observe phases, STOP binding, one immutable GRR, UNKNOWN capacity retention and discovered-container cleanup without relaunch. Existing function proacl/prosecdef/proconfig and a legacy data sentinel remain unchanged. Synthetic G1 and signature strings are local database fixtures only: neither is a real applicable Gate or signature proof. The first earlier run exposed only a test clock-sampling/rounding expectation issue; one shared sampled clock fixed it. Earlier source had nine passing Node tests before the new UNKNOWN cleanup check.

Private functions read_execution, reserve_gate, execution_transition, rotate_execution_generation and commit_gate_result serialize the same existing Root row with runtime state. service_role has function execution only; anonymous/authenticated clients and direct service-role table access are denied. Initial binding/current rows must be provisioned only after acceptance of their exact references; the installer supplies none. read_execution has authority_effect NONE. reserve_gate does not manufacture a GA: it persists exact externally verified bytes and conservatively charges a single attempt. Its same-key DUPLICATE is historical recovery, never new dispatch permission.

Budget starts from the previously reported conservative 1410 seconds and 19264968 bytes, rather than zero. The explicit Profile successor permits each new GA to reserve its complete <=180-second window and 128 MiB; the hard totals are still 7200 seconds and 1 GiB. This candidate does not extend the already signed 90-second Profile or any existing GA. No automatic refunds occur. UNKNOWN keeps the active slot even after expiration or revocation. An independently observed exact container may be attached to an UNKNOWN attempt for STOP; this does not restore CREATE/START authority. Release requires the one stopped decision reservation and immutable externally signed GRR.

The functions perform storage/current-state rejection checks, not full Schema or cryptographic acceptance. Actual complete Schema, Gate version/digest/applicability, controller qualification, Profile and four-layer N/A acceptance, accepted issuer algorithm, root currentness, signed generation changes, exact stopped evidence and signature proof must be verified by the trusted host before a write. JSON shape and SHA fields are insufficient. GRR proof carrier and its fixed private typed URI mapping are still part of the separate signature successor review; there is no live proof resolver here.

The only existing safe live transport is the root agent's authorized Supabase execute_sql tool. client.mjs takes an explicit trusted query callback, has a fixed project/root and parameterized statements, and never discovers or loads credentials. It is tested against local PostgreSQL; no actual Node-to-live-DB callback exists. A tool bridge may execute these fixed statements per action, using fresh results. It must not convert a saved readback into future currentness. SQL serialization does not claim to atomically fence a later external Docker action.

Applicable static Gate is a real remaining input: QualificationPhasePolicy's PRE_ENTRY_QUALIFICATION_GATE_AUTHORIZATION is an alias, not a registered Gate ID. Original G0a/G0b read-only targets and G7A RC requirements cannot be substituted, and R09 B01–B06/PQUAL case IDs cannot be renamed as Gates. This installer accepts only the original Registry enumeration and seeds no Gate. An exact applicable accepted definition or explicit controlled Registry successor is needed before provisioning; no frozen Registry is changed.

Use `node --test scripts/phase2-qualification/nonproduction-control-store/runtime-successor/store.test.mjs` for the disposable local check. Root owns any accepted installation/publication and real execution. This package supplies no GA, GRR, controller qualification or PQUAL PASS.

Review successor: the old source and 10-test result are retained under history/2ae5b4b9. Independent targeted PostgreSQL reproduction found two different GAs could reuse one GRR object ID and that read_execution varied by session timezone. The candidate now writes a globally unique receipt_id with the raw receipt in the same transaction, and pins read_execution to UTC. The assessor owns the targeted new PostgreSQL verification; the old 10 checks have not been re-run for this narrow change.

Remote-evidence successor preserves accepted 2a670 source under history/2a6708fc. Full synthetic Intent/Result raw strings and their SHA-256 are stored in the existing immutable execution_events table, bound to GA, operation and phase. Native recording_transaction_id prevents same-transaction Intent from authorizing a dispatch: the next transaction must read an already committed exact event. record_effect_intent and dispatch_recorded_intent are fixed wrappers around the existing serialized transition logic; historical duplicate calls remain DUPLICATE and never permit re-dispatch. Dispatch returns the exact prior Intent plus a fresh current_context (Root, binding, current state and one attempt), allowing the trusted host to verify current authority without another standalone SQL read. read_execution_event provides an exact narrow byte readback. Results remain observations, not GRRs.

The new disposable evidence.test.mjs run passed 6/6 Node-reported checks in 2951.5857 ms (four new targeted checks, the reused empty-install check and their parent). It covers the explicit 180-second bound, rejecting same-transaction dispatch, exact committed byte readback/current projection, idempotent wrapper recovery and complete Result persistence. A column/row alias ambiguity found during development was fixed before this result. The original broader test helper was adapted to supply mandatory Intent/Result bytes, without re-running its old ten checks. No live installation or remote write occurred.
