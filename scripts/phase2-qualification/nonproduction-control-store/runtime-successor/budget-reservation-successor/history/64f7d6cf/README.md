# Pre-GA budget reservation, same private control domain

This complete empty-install successor preserves the accepted `a242db8504f1cbd9c04ee8a22d8072e7b9ee0d6897433393e88c6e14a8e4ea27` installer. No runtime tables have yet been installed remotely. The final installation still adds exactly the same five tables, with the original Root tables, foreign keys and seed-before-execution boundary unchanged. No pre-binding authority, new Store, control root or object family is created.

The original runtime allocated budget only while storing the complete signed GA, which cannot itself provide that GA's prior budget reference. The accepted minimal direction treats only the budget instance reference as late-bound: runtime acceptance fixes its exact resolver and bounds; it does not pre-sign a nonexistent reservation. Once the actual accepted execution_binding/current rows exist, `reserve_execution_budget(raw,sha)` writes a complete immutable BUDGET_RESERVED record to the existing execution_events table and atomically charges 180 seconds plus 134,217,728 bytes. A single `current.pending_budget_sequence` holds the allocation. No GA identifier or GA hash occurs in this raw input.

The raw object has exactly fourteen fields: controller_digest, credential_generation, environment, evidence_bytes, expires_at, idempotency_key, not_before, profile_digest, purpose, root_generation, runner_generation, scope_digest, seconds, session_generation. It is bounded unique-key JSON with exact UTF-8 SHA-256. The fixed purpose/environment, current Root and three independent generations, exact accepted Profile/controller/scope, Owner interval and aggregate 7,200-second/1-GiB limits are checked under the existing lock order. Waiting for static signing is not executed compute time: reservation validity may extend within the Owner window, while allocated execution remains 180 seconds.

The reference encoding is the explicitly proposed same-domain evidence locator `urn:clued:control-evidence:uscrdifznmlvczcekqpw:execution-events:<sequence>`, with SHA-256 of the event's body.raw. This is not a claim that the original contract already defined a BudgetReservation wire URI. `read_execution_event(sequence)` returns the actual immutable row; request.operation is BUDGET_RESERVED and request.body contains the exact raw and sha256. Ordinary events and actual live GA/GRR remain in their existing types and stores.

After the complete GA has been signed, `reserve_gate` requires this exact prior-committed event, fixed reference, sole pending allocation, matching Root/Profile/controller/scope/generations, and a GA validity interval fully contained in the reservation interval with at most 180 seconds. It consumes once by storing immutable unique `attempt.budget_sequence` and clearing the pending pointer, while keeping the prior charge. Exact same-GA replay returns its old record; another GA cannot consume the same allocation. No second deduction occurs.

At runtime preflight/dispatch, the budget has already been consumed **by that exact GA**, so the verifier must resolve attempt.budget_sequence and require the immutable matching original event, rather than accepting any consumed reservation or requiring it still pending. No expiry, lost signing response, UNKNOWN, failed consume or duplicate reservation automatically refunds or releases capacity. A failed signing can therefore leave a charged pending allocation requiring separately evidenced recovery; this installer does not invent an automatic abandonment/refund operation.

Only the narrow reservation function is added to service_role's existing typed function access. Direct tables remain inaccessible and immutable records cannot be updated/deleted. No rows or privileges outside this fixed domain are changed. Actual signature and full runtime/source acceptance remain trusted-verifier duties; SQL persistence never issues a GA or controller qualification.
