# Runtime material assembly, without issuing anything

`prepare.mjs` covers every required GA field except the existing verifier's ten explicit dynamic fields. It produces a reviewable `PreparedExpectedGa.json`, never a signed GA, accepted runtime record, qualification, StatusManifest or executable capability. Forty-one fixed fields have individual source/meaning entries. Thirteen currently bind existing exact definitions or historical source references; twenty-eight require final exact inputs. Null means missing material, not an accepted N/A.

The actual R05–R10 historical objects are in `StageSourceMapping.json`. R05 is the architecture acceptance, R06 the structure freeze. R07/R08 deliberately share their real combined engineering decision. R09/R10 retain their original bounded engineering decision types. The original source bytes and actual blob references are preserved; this catalog does not rename them to unissued Kernel wire receipts. Their final applicability as runtime prerequisites is independently decided. The runtime reader can validate these unchanged files in actual signed PR29 commit `21bf9c073200d264feda31ee1f555db589ace8ed`; earlier independent signature reports remain evidence too.

Run `node scripts/phase2-qualification/RuntimeMaterialPreparation/prepare.mjs` to regenerate the preparation. The only optional input is the fixed local `work/bindings.json` file in this directory. It maps an unresolved field to `{value,provenance:{source,sha256}}`. The source description must identify actual bytes or a precise proposed material for review; provenance is never trusted by this tool as an authorization assertion. Each supplied value must satisfy its original GA field schema. Dynamic or already fixed fields cannot be overridden. Unknown schema fields fail closed, so a required schema change cannot silently fall out of the source map. The generator performs no network or database access and accepts no arbitrary source/output paths.

Final assembly must resolve these clusters rather than creating decorative references:

- Final accepted controller SourceManifest, Gate/Test input successor and actual source publication give the executor, target revision, fixtures, plan and artifacts. The old parent dependency and fixed action primitive alone cannot supply those identities.
- Actual current Root2 supplies authority/issuer references. Profile180 exact definition and its genuine independent acceptance reference are reusable now; its actual signature publication still needs the final verifier input.
- Full original StatusManifest lives in the private control store, including its real original STATUS signature binding. A statement that it is stored is not readback evidence.
- A real pre-GA budget reservation must exist independently of the complete future GA. The previously accepted `reserve_gate` allocated only after receiving GA bytes, so its row cannot be used as a self-referential budget digest. The coordinator has retained the empty installation while a same-domain immutable event reservation successor is prepared. No local token or fabricated reservation is substituted here.
- Actor, subject, repository, Binding, credential scope, risk, stop and recovery references need concrete accepted metadata and applicability. A generic document hash cannot stand in for a specifically required business receipt; nonexistent business-layer scopes remain only the already accepted, reasoned N/A vector. Original read/write/deny boundaries remain exact.

The tool intentionally always emits accepted=false, executable=false, ga_issued=false and requires final independent review even when every field is supplied. Four new pure assembly/schema rejection checks passed, 95.5583 ms, with no network, SQL, process or Skill action. The exact source files and generated output are indexed separately for review; no signature payload or operational authority is generated.
