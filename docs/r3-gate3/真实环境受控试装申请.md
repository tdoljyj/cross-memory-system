### 5. 执行顺序（预填：install → conformance → enable）

1. **备份**：按 §3 白名单快照到备份目录；
2. **install**：LifecycleController.install(binding_id) → ACTIVE/ADVISORY
   （install 默认 ADVISORY，不直接 ENFORCED）；
3. **conformance**：ConformanceVerifier.verify（receipt + .truth-state 强绑定 +
   证据新鲜度 + 声明 vs 实际）→ 输出档位；
4. **enable 前的再确认**：binding 状态、构件校验、Truth 能力检查；
5. **enable**：仅在 conformance 证据链完整且授权允许时才 ACTIVE；
   档位由 ConformanceVerifier 生成（不高于授权上限）。

### 6. 失败回滚及恢复到 ADVISORY（预填）

- install 失败：预检/事务失败 → 回滚无半成品（staging 清理 + 审计 rollback_complete）；
- conformance 失败：不 enable，保持 ADVISORY（或按状态回退）；
- enable 失败：回退 DISABLED/BROKEN → repair（保持 ADVISORY）或 uninstall（仅解绑当前）；
- 恢复方法：uninstall 只解绑当前 Binding（不删 canonical memory / 共享 Core）；
  purge **明确排除**（真实删除不授权）；
- 任意失败 → 立即停止，现场复核报告，恢复到 ADVISORY 后等待裁决。
