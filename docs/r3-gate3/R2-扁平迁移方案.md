# R2：扁平 → 目录 Binding 布局原子迁移方案（BINDING_LAYOUT_INCOMPATIBLE 收口）

- **状态**：**方案（本轮不执行实际迁移）**——产品所有者裁决："本轮不授权实际迁移"
- **对象**：真实扁平 Binding `codex-workbuddy-windows-primary.json`（Trial 3A 创建）
- **目标**：正式布局 `bindings/codex-workbuddy-windows-primary/binding.json`

---

## 1. 背景

- R3 install（Trial 3A）在 `bindings/` 下写入**扁平文件** `codex-workbuddy-windows-primary.json`；
- Clued 生命周期入口只识别 `bindings/<id>/binding.json`（目录布局）→ `find_by_agent`
  无法发现该 Binding（BINDING_LAYOUT_INCOMPATIBLE）；
- R2 代码已实现"单一规范写入（目录）+ 受控迁移兼容读（扁平）+ 双格式 fail-closed"。

## 2. 迁移原则（裁决）

- **单一规范写入**：`bindings/<id>/binding.json` 为正式生命周期布局；
- **迁移兼容读取**：扁平文件仅受控读（`_layout=flat-migration`），不写回；
- **双格式 fail-closed**：同一 Binding 同时出现扁平与目录 → `CLD-LAYOUT-001` 拒绝；
- **不形成两套并行真值**：迁移后扁平文件删除（属迁移步骤，非 purge）。

## 3. 迁移步骤（原子；失败恢复 ADVISORY）

```
Step 1 备份
  - 备份目录：.clued/backups/migrate-<ts>/
  - 内容：扁平文件 hex 快照 + 三轴状态 JSON + registry 现状（如有）
  - 校验：备份 SHA-256 与源一致

Step 2 转换（写入正式布局）
  - 读扁平（兼容读）→ 构造目录布局文件
  - 原子写 bindings/<id>/binding.json（tmp + os.replace）
  - 此刻双格式并存（扁平 + 目录）——仅迁移窗口内允许，由迁移工具持有

Step 3 校验
  - 目录布局可枚举（list_bindings 含该 binding）
  - find_by_agent 唯一定位；三轴状态无漂移（ACTIVE/ONLINE/ADVISORY）
  - 与迁移前扁平状态逐字段一致

Step 4 移除扁平（原子）
  - 备份 hex 已存 → 删除扁平文件
  - 移除后：仅目录布局（单一真值）；双格式检测通过

Step 5 失败恢复
  - 任一步失败 → 从备份恢复：写回扁平（若已删）或删除目录布局
  - 恢复后状态 = 迁移前（ACTIVE/ONLINE/ADVISORY）
  - 不触碰 canonical memory / 其他 Binding / 共享 Core / 冻结区
```
