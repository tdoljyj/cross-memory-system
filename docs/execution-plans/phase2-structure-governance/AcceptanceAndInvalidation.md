## 1. 使用方法与判定边界

每次晋级固定一个受审对象和基线版本，为本步骤各项要求关联精确证据，运行适用检查，记录剩余义务，再判断是否满足下一步入口。每步均保留一个明确下一动作。

既有 PASS 的历史事实不因本表新增而消失。本表核对的是：既有证据证明了什么、现今是否仍适用、进入下一步还缺什么。不得用 Step 18 的最终强制要求倒推所有前序步骤都必须先完成 Step 18；各阶段执行其对应规则。

区分两种状态，不能混用：

| 证据核对状态 | 含义 |
|---|---|
| VERIFIED | 本轮直接读取对应对象或实际运行，完成所声明范围的核验；必须写明核验范围 |
| DOCUMENTED | 来源中有明确声明，尚未直接核验其运行结果或全部关联对象 |
| UNKNOWN | 来源不可取回、受审对象不明确、缺少适用条件，或尚未完成检查 |
| CONTRADICTED | 可复核的直接证据与声明冲突，记录冲突双方，不能静默选择 |
| NOT_APPLICABLE_WITH_PROOF | 有范围合同与适用理由支持不适用，不能用作权限不足或工作未做的替代 |

| 步骤准入状态 | 含义 |
|---|---|
| READY_FOR_NEXT_STEP | 本步骤必需条件均有适用证据且无阻断义务；仅允许进入下一步已授权的工作 |
| NOT_READY | 缺少必需证据、条件不满足或发现阻断问题；保留已验证部分 |
| NOT_ASSESSED | 本轮没有评估，不代表失败或通过 |

运行结果保留原工具的 PASS/FAIL/ERROR/SKIPPED/NOT_EXECUTED。目标规则拒绝、工具故障、零测试、未运行分别记录。结论为 UNKNOWN 或 DOCUMENTED 的必需条件不能自动使步骤 READY。

## 2. 共同证据要求 E1–E6

- **E1 对象**：确切 subject、语义候选和包修订各自的版本轴、相关直接前任、commit/tree、输入内容摘要及范围。没有独立 run 的文档记录写明不适用，不能编造 run。
- **E2 来源**：证据生产者、工具/规则版本、工作流来源、运行标识与环境。记录实际认证方式和信任边界；内容哈希不代替签发者身份或授权验证。
- **E3 结果**：要求 → 检查 → 实际结果 → 证据位置。负例绑定变异范围、目标 Gate、预期失败原因和未变异对照。仅记录目标 Gate 红灯不足以证明全部规则覆盖。
- **E4 适用性**：证据对应的对象、规则、权限状态与外部状态；用于当前准入时按本表失效规则核查。历史证据永久保留其发生事实，不能永久用于当前准入。
- **E5 可取回**：保存证据位置、大小、摘要和访问边界；正式收口依赖的证据可在授权环境重新取回。过期 CI 链接不是永久留存证明；既有可靠持久副本可复用。
- **E6 结论边界**：每项缺口的负责人角色、处置、阻断性和下一动作；结论只覆盖实际检查范围。没有权限身份映射时不推定可签发 Acceptance/Freeze。

共同角色：执行者准备/运行；审查者核对；有既有授权的接受者签发 Step 10/11/19 等相应决定；发布者执行其范围内发布。一个人或工具是否可以兼任取决于既有授权及独立性合同，不由本表自动授予。

## 4. 统一失效与重入表

每份证据以实际输入依赖决定影响范围；不能仅凭步骤编号让全部后续证据自动失败，也不能认为只改一个文件就没有传播。与新 subject 不匹配的旧 PASS 仍可用于原 subject 的历史审计，不得直接用于新候选准入。

| ID / 触发 | 当前适用性处理 | 最小重核范围 | 后续决定与重入 |
|---|---|---|---|
| **I1 对象/内容变化**：candidate、source、schema、identity、alias、投影输入、包修订变化 | 新旧对象分开；计算内容差异与依赖影响；精确对象不匹配即不能复用为当前证据 | 直接依赖变化内容的 Gate，加上受影响聚合结果。整包摘要变化时重新验证包身份；不受影响底层证据只能在有明确复用证明时引用 | 重建相关候选证据集；接受/冻结仅适用于各自 subject；若接受范围受影响则复审和正式替换 |
| **I2 规则/工具变化**：validator、生成器、比较器、规则版本或信任配置 | 旧结果绑定旧规则；先评估规则差异与可兼容性 | 对受影响规则及其正负例、投影、语义比较进行重核；放宽规则需要既有授权，不能由被验证变更自批 | 依赖此规则有效性的审查与决定重新评估；无兼容证明则不得复用 |
| **I3 身份/授权变化**：owner、delegation、scope、签发者、撤销 | 历史执行事实保留；当前能力与准入重新判定 | 当前消费者权限、签发验证、相关入口；历史签名按已有签发时/撤销政策审计，不能凭空追溯改判 | 失去授权者不得继续签发或执行；按既有 revoke/supersede 机制处理有效决定 |
| **I4 外部/运行环境变化**：部署、配置、分支目标、运行消费者、外部快照 | 原结果只适用于原环境；说明哪些外部状态是该证据依赖 | 受影响来源重采、实际消费者/运行 Gate 复测；纯文件历史摘要不因无关部署变化失效 | 更新 source envelope 与环境绑定；未重核前标 UNKNOWN，不能称 current |
| **I5 证据不可取回/损坏**：失效链接、缺文件、摘要不符 | 可验证持久副本可替代临时位置；不可取回则当前可复核性未满足 | 从已登记可信副本恢复并重算摘要；没有副本则重建所需执行证据 | 不删除原记录；正式准入缺少必需证据时 NOT_READY，不能把链接存在当可取回 |
| **I6 依赖变化/发现缺陷**：上游复审、未知转冲突、归一化错误 | 创建影响列表，区分事实冲突、实现故障、测试不足和纯解释更正 | 回到最早受影响要求，重核依赖闭包；无关要求保留但需明确无影响依据 | 相关后续结论暂停用于新准入；问题处置后逐 Gate 重新进入，不重置全部历史 |
| **I7 操作/保护边界变化**：迁移中断、切换/恢复、写口复开、规则绕过 | 记录实际发生状态与停止点；不得用计划覆盖执行结果 | 恢复合同、当前写入路径、数据/身份对照及保护规则 | 先恢复或完成已授权动作并验证，再重新进入；权限或已冻结语义变更需对应授权 |
| **I8 证据记录纠错**：路径、标签、说明或引用修正 | 仅真正不影响对象/规则/权限/结论的元数据更正可不重跑执行；必须证明解析仍指向同一对象 | 引用/摘要/解析核对；若发现实体引用变化，升级 I1/I2/I3/I6 | 保留纠错差异与原记录，更新索引；不把改写 PASS/阶段位置当无害文字修正 |

发现触发 → 锁定变化内容 → 列出受影响要求/证据/决定 → 停止受影响准入 → 授权范围内修复/恢复 → 重核 → 重新出具适用结论。版本核对按任务触发，禁自动化；本表不增设启动或周期探针。
