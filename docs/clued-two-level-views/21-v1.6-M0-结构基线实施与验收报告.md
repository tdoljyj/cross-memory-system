## 1. 实施结果

新增单进程 M0 工具 `scripts/two-level-snapshot.mjs`，实现四个可重复动作：

1. `build`：从规范 Canonical Export 或 legacy `memory/objects` 冻结输入生成候选；
2. `validate`：校验 100% 文件清单、SHA-256、快照版本、迁移报告、Index 与计数；
3. `publish`：发布不可变版本；只有 `current + live_rechecked + views_complete=true` 才允许原子更新 `current.json`；
4. `rollback`：校验上一完整版本后原子恢复指针。

输出遵循 v1.6 机器路径：`profile.md`、`global/`、`projects/`、`objects/`、`events/raw/`、`evidence/`、`manifest.json` 和唯一 `index.json`。Manifest Schema 为 5；Event Rollup、Stream 排序扩展和 Receipt 正文导出均保持关闭。

## 2. 本次真实基线的限定

本次输入不是生产 Supabase 的 live export，而是已经与远端 `main` 对齐的仓库 `memory/objects`：

- 263 条旧 Memory Object；
- 4 个从旧 Project Scope 中发现的项目标识；
- 没有可证明的生产 canonical Record/Project/Event/Receipt ID 清单。

因此生成器没有把旧 ID 猜成生产 canonical ID，也没有自动做 Scope、类型、合并或正文语义变更。263 条旧 Record 与 4 个旧 Project 全部进入 `legacy_*` 兼容信封和 `pending_review`，最终结果为：

- `baseline_claim=historical_offline`；
- `source_verification=bundle_only`；
- `views_complete=false`；
- `pending_review=267`；
- 没有创建 `current.json`，没有改变生产正式入口。

该工件只能声明：“基于 `snap_e5a6daef8fbc934f3bdeff9b7de11a26` 的 M0 两级五视图结构基线已落地，未验证为生产最新；当前视图不完整，含 267 个待评审项。”
