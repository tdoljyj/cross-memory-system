# Clued 两级五视图：不变量与失败测试规格

> 状态：BASELINE SPEC / ADR 已确认，等待阶段 3 实现
> 日期：2026-08-24  
> 说明：本文件只冻结验收行为；阶段 2 才编写 SQL/API 测试代码。

## 1. 核心不变量测试

| ID | 场景 | 必须满足 | 失败判据 |
|---|---|---|---|
| CLD-VIEW-001 | 同一项目 Task 同时出现在 Global 与 Project | `id/version/body` 完全相同 | 产生两条记录或 ID 不同 |
| CLD-VIEW-002 | 项目改名 | 项目及所属记录 ID 不变，两个视图显示新名称 | 复制记录、旧名称仍为权威 |
| CLD-VIEW-003 | 合并两个项目 | 保留源/目标与记录 ID；新写入只到目标；正文不复制 | 记录数因正文复制增加、来源丢失 |
| CLD-VIEW-004 | 未确认 candidate 尝试创建五视图记录 | 整体拒绝且零副作用 | 产生 State/Task/Decision/Archive/Event |
| CLD-VIEW-005 | Event 含“当前状态”文本 | 当前 State 不受影响 | 当前视图从 Log 文本推导 |
| CLD-VIEW-006 | 替代 Decision | 新旧两条均保留，关系完整，旧条为 superseded | 原地覆盖或物理删除旧决策 |
| CLD-VIEW-007 | 归档当前记录 | 生成不可变摘要/引用而非复制 Event | Archive 与 Event 等价或可被更新 |
| CLD-VIEW-008 | 两客户端用同一旧 version 更新 | 仅一个成功，另一个显式冲突 | 静默 last-write-wins |
| CLD-VIEW-009 | 完成 Task 并推进 State 时 Event 写入失败 | Task、State、Event、Audit 全部回滚 | 出现部分成功 |
| CLD-VIEW-010 | 用户 A 读取/修改用户 B 记录 | 数据库层拒绝，服务层不泄露存在性 | 返回 B 的数据或修改成功 |
| CLD-VIEW-011 | 同用户跨项目错误 ID | 服务按目标项目边界拒绝 | 把记录移入/暴露给错误项目 |
| CLD-VIEW-012 | 查询当前 State/Now | 只查 current 记录与必要索引 | 必须扫描 Event 或 Markdown Log |

## 2. 写服务一致性测试

1. UI、REST API、MCP 对相同输入产生相同记录类型、状态、事件与审计字段。
2. 相同 idempotency key + 相同 payload 返回原结果，不新增记录或 Event。
3. 相同 idempotency key + 不同 payload 返回冲突。
4. 非法 Task 状态跳转被拒绝且零副作用。
5. `scope=global` 携带 `project_id`、或 `scope=project` 缺少 `project_id` 时被拒绝。
6. State 的 `next_task_id` 必须指向同一用户、同一 effective project 的可用 Task。
7. 删除 current 记录走归档/软删除语义，不发生无审计物理删除。

## 3. 项目生命周期回归

1. candidate 创建、重复发现、确认、驳回具有幂等行为。
2. 确认 candidate 时项目 ID 只创建一次。
3. rename 不改变项目 ID、业务记录 ID 或事件引用。
4. merge 遇到环、自合并、跨用户目标时拒绝。
5. 合并链解析到唯一 effective project；历史仍能显示原项目。
6. 合并后源项目只读，所有新写入定向目标项目。

## 4. RLS 与授权失败测试

1. anonymous、普通 authenticated、service/core 三类角色逐表验证 GRANT 与 RLS 的组合。
2. UPDATE 同时验证 `USING` 和 `WITH CHECK`；不得通过修改 `user_id/project_id` 越权。
3. security-invoker 视图不能绕过底表 RLS。
4. SECURITY DEFINER 核心不能从公开 schema 被任意调用；默认 PUBLIC EXECUTE 已撤销。
5. 浏览器 bundle 与运行时公开配置中不出现 service role key。
6. Security Advisor 不得新增 ERROR 或未建账 WARN。

## 5. 迁移 dry-run 测试

迁移开始前必须输出机器可读报告，至少包含：

- 每个来源文件/旧表的扫描行数、识别数、跳过数、冲突数。
- 旧对象 → 新 canonical ID 的 source map。
- 基于稳定来源键和内容指纹的去重结果。
- 不确定类型、项目归属、current 状态全部进入 manual review，不自动提升。
- 项目日志只迁移为 Event/evidence，不从自然语言自动生成当前 State/Task/Decision。
- 重跑 dry-run 和正式迁移均幂等。
- 回滚能按迁移批次撤销新增映射和记录，不影响迁移前数据。

失败条件：没有 source map、存在未解释丢行、冲突被静默覆盖、candidate 生成五视图记录、或需要先删除旧数据才能迁移。

## 6. API/MCP/UI 契约测试

- 列表响应明确包含 `id, version, record_type, project_id, status, updated_at`。
- 更新/删除缺 expected version 时返回可识别的 4xx 契约错误。
- 冲突响应包含当前 version，但不泄露其他用户正文。
- Global/Project 两级切换只改变过滤上下文，不创建或复制记录。
- 五视图共享固定 record type 枚举；未知类型被拒绝。
- 功能标志关闭时保持现有生产路径；打开时才进入新读写路径。

## 7. 可观测性与回滚验收

- 每个业务写入可用 request/idempotency key 关联业务记录、Event 和 Audit。
- 验收报告记录迁移版本、Worker version、功能标志、测试总数与失败数。
- 回滚演练必须证明：关闭 `project_views_v2` 后旧路径恢复；恢复前一 Worker 不依赖未完成的新 schema；当阶段新增记录可按批次识别。
