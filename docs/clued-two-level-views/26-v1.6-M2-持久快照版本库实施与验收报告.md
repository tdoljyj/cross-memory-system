日期：2026-08-26

## 结论

用户已明确授权执行 M2。按照 v1.6 的“按真实阈值逐项启用”合同，本次启用的具体能力是：**持久快照版本库、并发发布协调、有限重试、Reconciler、Sweeper/GC 与文件告警**。这组能力已通过对应的 16.3(2) 验收，可以声明“M2：持久快照运维能力已启用”。

Event Rollup/冷存储、索引分片、语义辅助和 Workspace/Team 未达到各自门禁，继续关闭；不得把本次结果表述为“M2 全部能力已启用”。Project/Record merge 写入也不属于本次启用范围。

## 触发依据

- 真实存在 Codex、WorkBuddy、DSH 三个消费者，超过持久版本库的 `minimum_consumers=2` 门槛。
- 启用时已有两个可验证不可变版本；随后使用 M2 协调发布入口完成一次真实 current 切换，最终版本库纳管 3 个 ready 版本。
- 当前指针继续只指向 `status=ready`、`views_stale=false`、`live_rechecked` 且 `views_complete=true` 的版本。

## 已启用能力

- `m2/store.json`：持久版本注册表、当前/上一版本、能力开关、保留策略、健康状态和告警状态。
- 独占发布锁：同一时间只允许一个 publish/reconcile/sweep 操作；锁等待使用 `100/500/2000ms` 有界退避，900 秒后才可自愈 stale lock。
- current CAS：协调发布必须提供 `expected_current_snapshot_version`；不匹配时以 `stale_current_pointer` 失败且不移动指针。
- Reconciler：重新验证 current 指针、manifest 哈希和全部注册版本；注册表漂移可自动修复，正式指针损坏只报告、绝不猜测切换。
- 文件告警：连续 3 次 reconcile 失败才进入 active alert；恢复后清零。
- Sweeper/GC：默认 dry-run；显式 `--apply` 也永远保护 current、previous 与至少 2 个最新 ready 版本，最多长期保留 12 个版本。
- runtime lock 目录被 Git 忽略，不把进程锁误当作持久事实。
