## 5. Worker 与 Supabase 评审

### 5.1 Cloudflare Worker

- compatibility date 为 `2026-08-23`，启用 `nodejs_compat`，Binding 由环境接口显式声明。
- 请求内状态均为局部值；未发现跨请求可变全局状态、未等待的 Promise、定时器、`passThroughOnException()` 调用或生产 secret 硬编码。
- Supabase publishable key 为公开客户端键，不具备 service-role 权限；用户数据请求仍携带用户 JWT 并由 RLS 限制。
- V2 只通过 `PROJECT_VIEWS_V2` 环境变量启用；hosting config 未声明该值，因此默认关闭。
- 当前 `@cloudflare/workers-types` 固定为 `4.20260702.1`，官方最新为 `5.20260823.1`；现有代码未使用新类型 API，记录为后续维护项，不在本阶段做无关升级。

### 5.2 Supabase/Postgres

- exposed `public` 表均显式启用 RLS；RLS policy 与 table/function grants 分开定义。
- V2 视图使用 `security_invoker=true`；privileged function 使用 `security definer set search_path=''` 并对 private core 撤销 public/anon/authenticated execute。
- account wrapper 以 `auth.uid()` 固定用户；Binding wrapper 先解析 hash-only token、scope 与 context key。
- update 同时具有 ownership `USING`/`WITH CHECK` 语义；legacy 直写仅允许 global note 的既有列，V2 记录只能进入 canonical transaction core。
- 当前 Supabase “新 public 表不再自动暴露”变更不会破坏本迁移：所需表、视图和函数均显式 revoke/grant；未依赖隐式默认权限。
