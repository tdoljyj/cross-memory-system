# 阶段 2：实体映射与最小数据变更

> 状态：G2 REVIEW CANDIDATE  
> 日期：2026-08-24  
> 输入：已确认 ADR、`main@84682ae`、现有 Memory CRUD、未应用的项目生命周期迁移 003。  
> 边界：本文件是物理设计，不是迁移 SQL；本阶段不改数据库或业务代码。

## 1. 结论

不新建“五视图表”，也不新建第二套项目系统。最小方案是：

1. 直接复用 `clued_projects` 与 `clued_project_mentions`。
2. 把现有 `clued_memories` 增量扩展为 Unified Record 的物理表。
3. 直接复用 `clued_context_events` 作为 Log，只补结构化关联列。
4. 直接复用 `clued_audit_receipts` 做事务回执与幂等账本；现有 `clued_memory_audit` 保留为兼容技术审计。
5. Global / Project / 五视图全部由同一表上的过滤和 `security_invoker` 视图生成，零正文复制。

物理业务表净新增数：**0**。后续迁移只对已有/待应用表补列、约束、索引、策略、函数和视图。

## 3. Unified Record 的物理映射

物理表继续叫 `public.clued_memories`；逻辑 API 层可称 `record`。现有字段不重命名，避免破坏旧 REST 路径：

| 逻辑字段 | 物理字段 | 变更 |
|---|---|---|
| `id` | `id` | 直接复用 UUID |
| `user_id` | `user_id` | 直接复用，RLS 首列索引保持 |
| `title` | `title` | 直接复用 |
| `body` | `content` | 逻辑别名，不改物理列名 |
| `created_at/updated_at` | 同名 | 直接复用 |
| `scope` | 新增 `scope text` | 默认 `global`；仅 `global/project` |
| `project_id` | 新增 `project_id uuid` | 可空，引用 `clued_projects(id)` |
| `record_type` | 新增 `record_type text` | 默认 `note`；五类见下 |
| `record_key` | 新增 `record_key text` | State/Decision 必填，表示稳定语义线程 |
| `status` | 新增 `status text` | 默认 `active`，由类型约束状态集合 |
| `priority` | 新增 `priority smallint` | 默认 0，范围 0–100；Now 仅按查询排序 |
| `version` | 新增 `version bigint` | 默认 1，乐观锁每次写 +1 |
| `source_ref` | 新增 `source_ref text` | 可空，最长 500；只记录来源引用 |
| `supersedes_id` | 新增自引用 UUID | Decision/State 替代链，旧记录不删除 |
| `restored_from_id` | 新增自引用 UUID | 恢复归档时指向旧快照 |
| `next_task_id` | 新增自引用 UUID | State 只引用下一 Task，不复制正文 |
| `archived_at` | 新增 timestamptz | current 记录为空，归档后有值 |

### 3.1 Record Type 与状态

| `record_type` | 合法 `status` | 特别约束 |
|---|---|---|
| `note` | `active`, `archived` | 兼容现有 Memory CRUD |
| `state` | `current`, `superseded`, `archived` | `record_key` 必填；每范围/key 最多一个 current |
| `task` | `backlog`, `ready`, `in_progress`, `blocked`, `done`, `cancelled`, `archived` | “一个 Now”不是唯一约束 |
| `decision` | `active`, `superseded`, `archived` | `record_key` 必填；替代时新建记录 |
| `archive_snapshot` | `archived` | 创建后业务路径不可更新 |

跨字段约束：

- `scope='global'` 时 `project_id is null`。
- `scope='project'` 时 `project_id is not null`。
- `record_type in ('state','decision')` 时 `record_key` 非空。
- `archived_at` 只表示显式归档：`status='archived'` 时必填，非 archived 时为空；Task 的 `done/cancelled` 和 Decision 的 `superseded` 可保持未归档，不能混同归档时间。
- `supersedes_id/restored_from_id/next_task_id` 不能等于自身 `id`。
- “项目必须已确认、未驳回、新写入必须落到 effective target”需要跨表读取，不能伪装成 CHECK；由唯一写服务在锁内验证。

### 3.2 唯一性与索引

必须新增：

1. `project_id`、三个自引用外键列各自建立索引。
2. 全局列表索引：`(user_id, record_type, status, priority desc, updated_at desc, id)`。
3. 项目列表索引：`(user_id, project_id, record_type, status, priority desc, updated_at desc, id)`。
4. 两个 partial unique index 保证 current State：
   - Global：`(user_id, record_key)`，条件为 global + state + current + 未归档。
   - Project：`(user_id, project_id, record_key)`，条件为 project + state + current + 未归档。
5. Decision 同样按 Global / Project 建“每个 `record_key` 一个 active”partial unique index。
6. Now 查询不建唯一索引；固定排序为 `priority desc, updated_at desc, id`。

## 4. Project Registry 的最小加固

迁移 003 保持历史，不重写、不 squash；生产顺序仍是先 003，再执行未来的 additive follow-up migration。

后续迁移需要通过 `CREATE OR REPLACE FUNCTION` 加固现有核心：

- Merge 前按项目 ID 升序加锁。
- 源和目标必须同一用户，且都是尚未合并的项目。
- 拒绝自合并、重复合并、跨用户合并与任何合并环。
- candidate/unconfirmed、dismissed 项目不得承载 Unified Record。
- Rename 只改 registry 字段；所有记录/事件保持原 `project_id`。
- Merge 不批量改写记录的 `project_id`；查询解析 `effective_project_id`，新写入只用目标 ID。
- 若源/目标有同 key current State，目标保持 current，源 State 原子归档并记录 Event。

## 5. Event 与 Audit 的最小扩展

### `clued_context_events`

新增可空关联列：

- `project_id uuid references clued_projects(id) on delete set null`
- `record_id uuid references clued_memories(id) on delete set null`
- `record_version bigint`

已有 `context_key/version/idempotency_key/payload/occurred_at` 继续复用。Event 只追加；业务写服务不得提供 UPDATE/DELETE 入口。当前事实查询不得扫描该表。

### `clued_audit_receipts`

新增：

- `idempotency_key text`（8–160 字符，可空以兼容历史）
- `request_sha256 text`（64 位小写十六进制，可空以兼容历史）

新增 partial unique index：`(user_id, context_key, idempotency_key) where idempotency_key is not null`。相同 key + 相同摘要返回 metadata 中的原结果；相同 key + 不同摘要返回冲突。

`clued_memory_audit` 不承担幂等或业务事件，只保留现有 digest-only trigger。V2 事务同时生成 Event 与 Receipt；兼容 trigger 产生的摘要审计属于技术层，不构成第二份业务记录。

## 6. 派生视图

阶段 4 最多新增三个 `security_invoker` 只读视图：

1. `clued_project_resolution_v2`：原项目 ID → effective project ID；保留 source identity，拒绝环。
2. `clued_records_v2`：把 `content` 暴露为逻辑 `body`，并附 effective project ID。
3. `clued_global_work_v2`：只做默认 Global 聚合排序，不存正文、不使用 materialized view。

Project 五视图直接查询 `clued_records_v2 where effective_project_id = :project_id and record_type = :type`；Global 五视图去掉项目过滤。相同记录在两级视图中始终返回同一 `id/version/body`。

## 7. 明确不做

- 不创建十张视图实体表或五张正文表。
- 不把 `clued_projects.summary/progress_status` 扩展成版本化 State 正文。
- 不把 checkpoint、日志 Markdown 或 Event payload 当 current State。
- 不物理搬迁 merge 源项目的记录正文。
- 不在阶段 2 修改 API、MCP、UI、Skill、生产 schema 或数据。
