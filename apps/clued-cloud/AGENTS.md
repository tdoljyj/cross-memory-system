# BeamingFace Cloud continuity rules

These rules apply to every task under `apps/clued-cloud/`, in addition to the root `AGENTS.md`.

1. Use the unified `clued` Skill at `skills/clued/SKILL.md` in the repository root. Load its `references/engineering.md` for BeamingFace engineering or `references/memory-operations.md` for authorized context operations, according to the requested operation. These workflows share an authorized connection without granting or combining privileges. The former independent developer, user and continuity entries are retired; do not restore duplicate active Skills.
2. BeamingFace use (start, read order, capture of material outcomes, write discipline, checkpoint, storage boundaries) follows the single contract `protocol/agent/agent-contract.md`. The Worker serves that file at `/clued-agent.md` from `worker/generated/agent-contract.ts`; after editing the contract, run `node scripts/generate-agent-contract.mjs` and commit both files.
3. The deployed v1 schema still exposes legacy Project `certainty_status`, but do not extend it as product semantics. The accepted successor direction is `development/contracts/project-lifecycle/ProjectLifecycleSuccessor.v0.1.md`: once BeamingFace recognizes something as a Project it becomes a Project, while recognition confidence remains metadata. Until that successor is implemented and deployed, preserve the current production contract and do not silently bulk-promote legacy rows.
4. Identify the exact execution target. Keep ChatGPT Sites separate from production Worker `clued-cloud`. The adopted brand domains are `https://beamingface.com` (production) and `https://dev.beamingface.com` (development); this source rename does not establish that either has been deployed. The existing website/Connect route remains `https://kooyomi.com` until a verified cutover. The existing `kooyumi.pixelgrav.com` and `clued.pixelgrav.com` MCP/OAuth origins retain their own resource, issuer and Binding identities.
5. Use scoped maturity language. A kernel or migration milestone does not imply that the whole cloud product is mature.

Deployment, DNS, Binding, Secret, Schema, purge, merge, tag and release actions require their own authorization unless already included in the user-approved gate.
