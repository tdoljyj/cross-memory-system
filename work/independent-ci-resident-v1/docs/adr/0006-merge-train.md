# ADR 0006：合并列车

- 状态：生效（strict 相关部分由 [ADR 0007](0007-strict-permanent.md) 改写）
- 日期：2026-10-31
- Owner Decision：`263f9701`（现在开车，批量测试与二分排在后面）；`3dcb583b`（车头后面按 Task 优先级排位，取代 `a5ea4be3`）；`86008583`（守队程序只碰 GitHub）；`60803c41`（保留只碰 GitHub 的守队程序，不改用 GitHub 原生 auto-merge）；`349f6e42`（排队协调由列车承担）
- 档案：DESIGN §38、§41

## 背景

多个 PR 各自测完、各自合入时，后合入的 PR 测的是旧 main。两个各自变绿的 PR 合在一起可能就是红的。

## 决定

- **车头**：KooYomi 合并队列第 1 位的认领，由服务端一次写定。只有车头能拿到 `kooyumi-merge-slot` 的绿。
- **车头批次**：测 GitHub 的试合并提交 S（父提交为 [T, H]），S 只能由 on 模式第 10 段产生。每个 head 最多两次。
- **排位**：车头后面按 Task 优先级，同优先级按入队时间。排位开关默认 `fifo`。
- **守队程序**（`.github` 工作流）：列车模式下只合车头，只用 merge 方式。
- **多节点**：on 模式只在当班节点跑；所有节点必须同一 Source。

## 理由

- 让"测过的东西"和"落地的东西"一致，同时保持一次只合一个的简单模型。
- 批量合并和二分是下一步（[ADR 0010](0010-bors-preauthorized.md)）。

## 后果

- 车头批次要多跑一遍第 1–7 段。
- 原设计要求"开车前关 strict、完成全量清扫"，已被 [ADR 0007](0007-strict-permanent.md) 和 [ADR 0008](0008-full-sweep-audit.md) 取代。
