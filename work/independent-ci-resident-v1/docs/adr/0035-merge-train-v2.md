# ADR 0035：合并列车 v2 的工作领用与批次落地

- 状态：提议，随 v2 片 7 通过后生效。
- 日期：2026-11-26
- 框架变更依据：Owner Decision `b57ec3ac`；《合并列车 v2 设计与实施计划》第五节。下列编号对应 2026-11-22 CI/CD 框架。
- 适用范围：合并列车 v2。生产切换须通过片 7 的混版隔离、迁移、升级、故障演练及落地端验证。片 8 终态删旧还须通过真实 C7 验收。

| 条款 | v2 合同 |

## §2.2 准入与首次入队

第 1 段对精确 H 做 Native 完整准入。确认发布票据、持有代次和外部检查 ID 后，以同一事务结清准入发布并登记“评估首次入队”待办。任一合格节点可由事件或定向补查领取待办，按当前的必需检查、Grant、PR 状态、H 和认领代次决定入队、等待、归还队位或剔除旧 head。入队效果按精确对象去重。此前从未入队的 PR 也从此接续到落地。第 8 段专责落地准入和 main 更新。

## §2.4 组批、落地与收尾

1. 服务端核对节点资格、Binding、机器签名及接受的 Source，按 Native 队序原子封存批成员并发给工作项租约。合格节点可分别接续组批、等检查、落地、二分和收尾。等待外部 CI 时释放本机执行槽。空闲时即时开批，稳态每批 1–3 个 PR，沿用描述符 `/4` 的硬上限 4。多人批按 [ADR 0019](0019-train-batch-member-chain.md) 验证有序成员链。只有归因到合成树的终局失败才触发前缀二分。绿前缀落地后，余项以实际 main 重新组批。
2. 组批使用按批和代次隔离的受保护临时引用。封存的 S 经当前代次发布到固定的 `clued-train/staging`，由该引用触发必需 CI。落地前实时核对 strict、主规则集、独立快进规则集、每个成员的 Native 准入和精确 H、认领代次、队位、Grant、撤销、冻结、Source，以及 T、S 的父链和树。按当前规则在 **S 本身**核验最新的必需检查与 App 来源。保留无人发布的 `kooyumi-train-landed` 封住 PR 页面合入。
3. 可信落地端先登记批次、代次、T、S、成员和有效期，目标分支只允许一项未裁决的 main 写意图。由 App 5368905 经 GitHub 原子 `updateRefs` 同时比较 main 的预期尖端 T 和受保护代次引用的预期值 G，快进 main 到 S 并推进到唯一的落地完成标记。取消与接手通过同一个 G 的比较交换裁决。错 T、错 G 或规则不满足时 main 零更新。主规则集旁路只含该 App，独立规则集禁止删除和非快进，旁路为空。
4. 写入结果不明时保留未结意图，核对远端两份引用及祖先关系后再裁决。已证实落地时按共享批记录逐成员幂等 adopt，核对 PR、H、claim、fence、epoch，接手节点从未结成员接续。只有核实原外部检查身份后才允许撤回指定效果。

片 7 须在等价规则下证明 App 的双引用更新同成同败，包括旧代次迟到、main 已走到 S 的中间祖先、成功后丢失回执。切换时先排空或隔离旧写者，再签发 v2 代次。生产先按单员验证，连续五个零人工落地后才按 C6 和接受的船队策略升到 3。旧路径的终态清理按真实 C7 验收执行。

## §2.7 节点升级与首装

全队以 Owner 接受、服务端核准的船队 Source 清单为资格基准，节点逐台与该清单核对。Source 不符的节点停止领取，其他已满足同一基准且合格的节点可继续。沿用通用升级和通用重装，使用同一个经接受的包。

## §2.8、Z14 观测、局部 HALT 与全队停止

- **局部 HALT**保留故障节点现场，只有 Owner 走既有复位入口恢复该节点。其他合格节点可处理独立工作，或在旧代次和在途效果裁决后接续同一工作。
- **全队停止**由 Owner 全队急停、`frozen` 或 strict 关闭等全队安全门触发，阻止落地。换节点不能绕过。涉及单一未裁决外部写的等待应标明受影响对象及原因。
- 面板只显示批次、成员、当前阶段、原因、下一次自动处理时刻。当前没有自动处理安排时，明确显示“无”。
