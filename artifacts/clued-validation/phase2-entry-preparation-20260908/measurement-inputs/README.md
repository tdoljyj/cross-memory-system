# Slice A 测量输入核对

仅核对指定三份原合同；不运行待资格 Skill、模型或 Slice A，不签接受。完整来源路径、原始字节摘要、24 项清单及未改动阈值保存在 [InputReadiness.json](InputReadiness.json)。

**结构完整，执行输入尚未固定：24 cases = 16 正常 + 8 预期阻断，每 case 3 次，共 72 槽位。** 统计单位为 case，不能把三次重复当作三份独立样本。24 个 Gold 摘要全部为空，fixtures_built=false、datasets_and_gold_created=false、actual_dataset_digest=null。场景只有文字设计，没有可直接运行的来源会话、对象 ID/版本或固定 Gold 字节。

独立任务代理另外编写了 `GoldCandidate.private.json`：12 个 case 各有两段实际合成会话文本、明确任务和客观期望字段。状态为 **INDEPENDENT_AGENT_AUTHORED_NOT_ACCEPTED_NOT_FROZEN**，无运行结果；它不修改原合同的 Gold 空值，不冒充已获外部 Gold 或合格评测 Owner。主控与实现代理只接收路径、摘要和完备性，不读取答案正文；共享工作区本身不提供 OS 保密边界。

覆盖 SA-N01–N07、N09、N10、N14–N16。余下 N08/N11/N12/N13 和全部 8 个阻断 case 需要实际重建、产物、checkpoint、执行角色、授权身份及 Registry/无副作用绑定；未臆造这些运行语义。12 个候选使用逻辑 fixture ID，不能直接当作已创建 Canonical ID。固定真实绑定、评测 rubric 和保管规则后才可独立接受并冻结。

不另造 72 行空表：已有 case ID 与重复次数足以无歧义生成槽位，当前缺少精确 fixture/Gold 和冷热/seed 分配，空表不会增加信息。最小下一步是一次固定这组测量输入并接受原阈值，再由实际受权执行器生成 72 槽位及事件记录；不让实现者生成的答案冒充独立盲评 Gold。原合同的历史候选授权缺失只说明这三份文件未含实际绑定，不据此断言所有当前外部来源均不存在。
