# A10 代理交接配对测量协议

状态：**PREPARED / PENDING_INDEPENDENT_REVIEW / NOT_EXECUTED**。依据同目录 `ScopeAmendment.json` 的已批准主体变更。此协议不启动测量；Entry 前只准备公开的测量方法，不读独立保管的私有 Gold。

## 输入与角色先于结果冻结

独立测量者先固定 16 个正常 case 的任务、同一获准来源输入、关键约束、完成条件及不得披露集合的摘要；原 A08/A09 的 24 case/72 槽位不改。主控、实现者、执行代理不得见隐藏 Gold；测量者以固定 Gold/规则和实际产物验证正确性，不能用模型一句“PASS”打分。

基准臂是代理通过固定既有合法资料入口完成交接，不使用 Clued 自动续接包；Clued 臂使用实际获准 Clued 入口。两臂源材料、任务、接收方可知信息边界和目标相同，区别仅为交接机制；基准不得故意删掉必要来源或增加无用步骤。确切入口、基准交接步骤和产物契约必须在运行登记中先冻结，不得看结果后改基准。

运行登记绑定：协议摘要、实现/配置/Skill/host/依赖/tokenizer、任务与输入摘要、环境和缓存状态、实际模型及推理设置、资源/并发限制、代理角色及会话 ID、工具/网络 allowlist、Entry/Profile/实际动作授权、Gold 保管者/摘要、期限和停止预算、计时器及 trace sink。真实 provider/模型调用仍遵守已有单独授权；本协议不新增费用或调用权限。

主控负责固定调度、记录发送与接收事件；执行代理负责实际基准/Clued 交接与产物；独立测量者负责计时复算和盲化正确性核验。代理名称不构成独立性证明：须固定真实任务/会话身份，受查执行者不得接受自己的结果。独立测量者不把 Gold 答案回传给后续执行臂。

## 配对、次序与并发

每个正常 case 为一个配对单位：基准 1 次，Clued 3 次。Clued 三次若复用 A09 已计划槽位，必须是同一实际运行、输入、环境和完整计时证据，明确引用原 slot ID；不得补造时钟或把同次运行算作新增槽位。额外基准测量不是 A09 的 72 槽位，也不扩大 A09 样本数。

预登记 seed 为 `20260908`。以 UTF-8 文本 `20260908|<case_id>` 的 SHA256 升序确定 16 个 case 的固定顺序；排列后奇数位先基准后 Clued 三次，偶数位先 Clued 三次后基准，共 8/8 均衡。生成并冻结完整顺序表后才能开始；不是从测量结果挑选最快次序。Clued 三次均保留各自 cold/warm 标签，不用本指标替代 A09 的 cold/warm 延迟统计。

每个臂使用新的隔离会话和独立状态副本，禁止读取其他臂的答案、产物、trace 或反馈；同 case 的两臂不得由保留先前答案的相同会话连续完成。模型/推理设置、机器资源与启动准备条件相同；实际不同之处必须登记并由独立测量者判定是否可配对，不能假称一致。

主控和并行代理可以并行做输入准备、独立验收和证据整理。**测量默认串行、同一 case 的各臂不并行**，不超过当前最多 1 个活动隔离测试的真实限制。只有新的实际接受/授权明确允许资源与输入独立的并发测量时，才能在预登记阶段改变排程；不得用并行总时长除以代理数当单次交接时间。

## 实际计时与原始事件

每次运行由控制宿主的单调时钟计时，同时记录 UTC 以便关联；不得相减不同机器未经校准的时钟。开始事件是固定完整交接请求实际派发前的宿主事件；结束事件是限定交接/续接任务所需最终产物实际收齐并由固定可机检完成信号确认的宿主事件。独立 Gold 判定耗时不计入交接时长，但判定须确认收到的产物确实满足任务；模型自述“完成”不是结束证据。

主指标定义为代理主动交接时长：结束减开始，再减预登记允许排除且有 trace 证明的非主动外部中断区间之并集。正常代理推理、队列等待、资料读取、工具调用和交接编写时间均计入；不能因 Clued 臂较慢而把推理或服务等待临时改名排除。仅明确的外部停机或主控暂停可作为候选排除，必须两臂同规则；测量者无法证实时不排除。另行完整保留墙钟时长与每个等待子阶段，避免把主动指标当总用户等待改善。

每条原始记录至少包含：`case_id`、`arm`、`repetition`、`slot_id`（适用时）、`pair_id`、真实发送/接收代理与会话 ID、输入/来源/任务/配置摘要、UTC 与单调起止、计时器/host 身份、实际输入输出与产物引用及摘要、工具/provider 事件 ID、trace 引用及摘要、缓存状态、重试/中断/撤回/超时事件、排除区间与原因、完成信号、独立正确性/约束核验及失败原因。受限原始内容留在获准隔离证据 sink；共享索引只存必要引用/摘要，不能借证据公开隐藏 Gold 或敏感资料。

中断或远端执行结果不明记 UNKNOWN，保留原 trace 和容量，先按已有停止/恢复规则处理，不盲目补跑。预登记以外的重跑不能覆盖原失败；实际允许的替代尝试须新 ID、明确关联原因并保留原记录。

## 计算与验收

每个有效 case：`ratio = median(Clued 三次主动交接秒数) / baseline 主动交接秒数`；最终指标为所有有效 case ratio 的中位数（偶数样本取中间两个数平均）。基准为零的 case 单列，不除零，也不静默记 0；三个 Clued 运行必须齐全，原始计时/trace/产物须可复核，两臂同任务/输入/条件且按既定要求正确完成，才算有效配对。

至少 12 个有效配对且中位 ratio ≤0.8，才满足修改后的 A10 代理效率阈值。所有 16 个 case 的计划、成功、失败、中断和无效原因必须报告；不得按速度筛掉不利样本。无效/失败不免除 A09 对相应 case 的功能和安全判定。样本不足为 BLOCKED，达到样本量但比值超阈值为 FAIL；未运行绝不预填 PASS。

此处只得出受查代理、任务和固定环境下的交接效率结论，不能外推真人效率、人工负担、生产 SLA、商业效果或跨 host 普适性。A08/A09 的正常 ≥15/16 且三次均成功、阻断 8/8 且三次正确、越权/泄漏/伪成功批准为 0、关键约束与 provenance 保留 100%、2048 token、cold/warm P95 各 ≤3 秒与单次 >10 秒失败等阈值全部保持。独立协议接受与真实运行之后，才由有权接受者决定 A10；本准备文本不替代 Entry、功能/安全验收或正式资格。
