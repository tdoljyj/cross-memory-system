# 存储模块缓存细则 v0.1

## 1. 适用关系与第一阶段边界

本细则从属于 [Clued 缓存治理规范](../cache/CacheGovernance.v0.1.md)，遵守其
审核 → 精确版本归档 → 实施/验证的门禁。沿用同一 Storage Task，不建立新的
Program、账号权限系统、缓存清理器或业务记忆双写。

第一阶段验证既有本机只读工程镜像及其备份机制，复用已有实现；不在本次顺带
新增 Provider 元数据持久缓存、手机/平板离线库或文件正文离线副本。
后续类别接入必须满足统一规范且有自己的精确资格和保留合同。
本合同不证明账号 Agent 文件入口、所有存储提供方或所有设备已经可用。

## 2. 数据与现有机制映射

| 对象 | 本次处理 |
| --- | --- |
| 只读 Canonical 导出镜像及替换后备份 | 首个验证对象；保持派生、只读、带历史边界 |
| Provider 文件名、父目录、版本等元数据 | 同样属于敏感数据；不默认启用持久缓存，不能作为 mutation 准入权威 |
| Google refresh token、加密密钥、账号会话 | 服务端或既有批准的秘密保管；禁止复制到镜像/备份 |
| job/attempt、幂等账本、provider-root 围栏、admission、回执 | 沿用各自执行/安全状态合同；不归入缓存清理 |
| 真实资料、唯一离线编辑、治理 Evidence | 不迁移、不清理，不因字节重复获得删除权限 |

只读镜像从版本化来源重建，但来源不是在线当前权威。在线当前状态和操作权限
仍向已认证 Clued 服务核对；镜像只证明自己的完整性与 as-of 边界。

## 3. 位置与身份登记

本机路径只存在 endpoint-local 配置；可重建镜像与其备份使用同一已批准应用
缓存边界内的独立目录。不要把某 Windows 用户名、安装包 ID、盘符或批准的
物理路径写成所有端默认值。跨设备使用同一账号规则，不复制本机配置或凭据。

复用 `config/clued-endpoint-trust.json` 中独立 Owner/Scope 信任及既有 endpoint
配置，绑定单一账号和明确环境；不是多账号共享目录。环境隔离尚无机器证据时，
不得宣称已具备多环境自动隔离。路径登记还要明确模块、数据类和负责组件。

Windows 应用虚拟化可能让逻辑路径对应不同实际位置。验证完整结果中的实际
目录/卷身份、访问保护和内容证据；变化必须重新验证或停止复用。不得重写
Generation 指纹、关闭安全软件、扩大解释器访问或改 ACL 来获得 PASS。
检测到禁止位置时，停止新的持久化/复用并报告；不擅自搬走或删除原数据。

## 4. 既有镜像生命周期

| 要求 | 复用的工程入口/合同 |
| --- | --- |
| 确定源码、候选、目标验证 | `sync-memory.ps1 -AlignAndVerify -Access <scope>` / `sync-memory.py align-and-verify <scope>` |
| 零读取与不写 Canonical | `Access NONE` 零读 no-op；业务 push 保持拒绝 |
| 目标隔离、原子切换、并发与防倒退 | 既有 isolated mirror coordinator 与 request verification context |
| 所有者、Manifest 和源身份 | 独立 endpoint trust、内容哈希、版本化来源与实际路径身份 |
| 备份保留、最低恢复副本和保留阻止 | `config/clued-local-mirror-backup-policy.json` |
| 替换/no-op/清理审计 | 既有 `clued.local-mirror-audit.v1` |

不在此复制保留数值，也不另设一套参数：实际政策版本和原配置是验收对象。
现有备份数量/年龄政策不等于总字节硬限额。必须观察源/镜像/候选/备份的空间
需要；磁盘不足时保留原可验证副本并停止新增，不用危险清理腾空间。
全盘字节配额控制尚未实现的部分在验收表明确为缺口（Task `c7deadf4`），不以本文声称已实现。

失效条件至少覆盖 Owner/Scope、配置环境、路径身份/访问保护、Manifest、
源 commit/版本/格式、授权/时钟/TTL、校验器和发布指针变化。完整检查失败
不能以中途的 doctor PASS 替代；请求专属 Evidence 不跨请求/进程/设备复用。

历史快照只在已有、仍适用的离线读取授权内使用；本细则不新增离线授权。
退出、换账号、失去授权后停止对应新读/复用，按既有保留合同保留或擦除；
若端点无法实现该访问边界，该端点不得提供相应受保护的离线读取能力。
任何镜像或元数据都不能替代 fresh Artifact/Currentness 和 exact admission。

## 5. 迁移与清理

迁移前验证精确目标；优先从授权源重建，不移动唯一数据或复制 Google 凭据。
保留原缓存/备份和失败证据，完整校验新目标后才切换。失败时保留此前状态，
不抹除失败日志、原执行围栏，也不自动回退到已撤权缓存。
已完成的本机授权迁移是单次事实，不是其他端或其他目录的迁移许可。

清理只交给既有 coordinator/保留合同。每次动作重新核对精确目标，不删除
活动镜像、活动/受保护候选、最低已验证 LKG、Legal Hold 或未决执行状态。
已判定废弃的候选仍按原 coordinator 恢复/清理合同处理，不能只凭年龄判定。
本次文档批准
不授权立即清空旧目录或失败 Generation。未决状态与普通缓存保持物理/逻辑隔离。

## 6. 审核后第一阶段验收清单

每项记录“已验证 / 缺口 / 不适用（理由）”，引用精确源码、测试及端点证据；
不能只凭合同描述打勾。不满足项保持相关能力关闭或明确限定原有能力范围。

1. 精确逻辑/物理位置、单一 Owner/Scope/环境、禁止位置和秘密/持久状态排除。
2. 新请求走原统一入口；Source/Candidate/Mirror 全验证及最终 Evidence 一致；
   `NONE` 零读；不能跨请求复用 PASS 或把历史快照当 Current。
3. 损坏、部分写、路径别名/替换、身份或环境变更、换账号和授权失效的负例。
4. 并发刷新/切换、旧版本后到、进程失败、磁盘不足，不破坏原镜像及恢复边界。
5. 按现有保留政策验证活动目标/候选/LKG/Legal Hold 保护与精确删除范围；
   使用隔离测试对象，不以测试为由删除旧真实缓存。
6. 迁移完整校验、失败保持原状态、原目录保留、系统防护不变；未复制凭据。
7. 明列尚缺的统一自动位置检测、字节配额（Task `c7deadf4`）或平台接入等能力缺口；不得将本机
   检查结果泛化为浏览器、手机、平板、Dropbox 或其他模块资格。

已存在的镜像回归可复用代码，必须报告这次实际执行结果。只完成审核和归档
时，实施状态仍为待验证；后续变更需测试、审查和相关发布门禁，另记实际结果。
