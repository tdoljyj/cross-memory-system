# 用户画像 · 长期记忆

> 最后更新：2026-08-23 · 补充任务独立闭环约束

## 一句话
强烈偏「创造者 + 产品构建者 + 技术实践者」，正从专职 3D 动画师向独立游戏制作人 / 工作室主理人转型；追求把审美、动作、技术、工具、作品真正落地，不停在概念层。

## 身份轨迹
视觉传达 → 3D 动画 → 动画工具开发 → 技术型动画师 → 游戏动画 / 游戏制作 → 独立游戏项目 → 工作室 / IP。长期深度使用 Maya。当前处于「个人专业能力 → 个人作品与组织能力」的关键转型期。
制作思路正在转变：关注点从「怎么做」转向「我要做什么」——从技术执行者向作品负责人迁移。

## 技术能力
- 三维动画 / Maya（长期深度使用）
- Maya Python、MEL、PySide2、OpenMaya
- 动画曲线、IK / Foot Lock、Motion Correction、自动化工作流、插件与工具架构
- UE、游戏动画系统、游戏原型、AI 辅助开发
- 自研工具：GroundMate、MotionCorrector、Atlas
- 思维已从「怎么把动画做出来」升级为「为什么必须这么做？能不能变成系统？」
- 思维跨度：单个功能 → 工具 → 工作流 → 系统 → 平台 → 产品（Atlas 是例证：Core / Engine / SDK / Cloud / Marketplace / AI / Event Bus / Data Model 等，已接近平台思维）

## 真正想做的事（游戏）
- 理想：东方幻想 + 高质量动作 + 3D + 强叙事 + 东方美学 + 神话体系 + 宿命感 + 大世界观
- 参考：山海经、上古神话、天庭、夸父逐日、东方哲学、宏大叙事
- 定位：东方文化底层 + 现代 3A/主机动作游戏表现形式的独立游戏（不是手游 / 纯小游戏）
- 项目名方向：《山川夜语：逐日》
- 两条主线：① UE 游戏原型（核心玩法 / 动作 / 战斗 / 角色 / UE / 动画 / 系统 / 可玩性）② 剧情编剧（世界观 / 角色 / 神话 / 叙事）

## 审美
- 东方但不古装化；神话但不仙侠化；文学但不文艺腔；宏大但不喊口号；高级但不装；现代但不欧美模板化
- 喜欢：自然、天地、山川、日月、神话、宿命、生命、时间；「留白」，不喜欢「解释」
- 讨厌：龙凤祥云、青瓦白墙、水墨套路、玄天 / 苍穹 / 九州式词汇堆砌
- 本质：在现代语境下重新解释东方神话
- 判断标准常是「有没有感觉」而非「能不能用」；对「气质」极其敏感（视觉化思维：先看「看起来对不对」）

## 工作室命名
- 候选池：鱼景、鱼乐、鱼火、与火、于火、松鱼、熊火、月禾、禾月、禾景夕色、戏影、影戏堂
- 标准：陌生但自然、简单但有气质、有画面感、没有廉价造词痕迹
- 讨厌：明显 AI 造词、四字成语式、过度文艺/古风、一眼「游戏公司/文化传媒」、生硬堆砌神话元素、为寓意而寓意
- 当前倾向「鱼火」：鱼普通、火普通，组合不常见、无需解释，方向对
- 名字的意义：不是注册公司用，而是未来所有作品的精神入口、作品品牌（对品牌身份高度敏感）

## 工作方式（对 AI / 工具的要求）
- 结果导向，讨厌长时间抽象讨论；高频词：「直接给我」「完整版本」「详细规划」「不要废话」「继续」「你再想想」「你完全理解错了」「不是这个意思」
- 能接受复杂和详细，但「详细」= 有效信息密度高，不是「背景 + 免责声明 + 空泛总结」
- 高信息密度型用户：不怕复杂，怕浪费时间
- 对需求理解敏感：先理解原逻辑 → 找真正问题 → 最小范围修改 → 保留既有行为 → 给完整可运行版本；「更好」不等于「兼容」
- 对无风险、可逆、在任务范围内的合理操作直接执行，不要反复请求确认；只有破坏性/不可逆/越界/需外部授权才停下问
- 任务必须按独立闭环单元完成：每一步结束即固化、校验并上传全部后续所需产物；完成即了结，禁止后续追索旧电脑、本机临时文件、孤儿提交或未上传的前序证据，不把历史保存责任转嫁给用户
- 理想 AI：能进入工作上下文、跟着思路推进的「项目记忆型搭档」，不是百科全书或搜索框

## 软件工程态度
- 软件是实现目标的工具，不是目标本身；成熟方案优先，不从零造轮子、不为架构而架构
- 表面上矛盾：一边「有成熟方案就用」，一边自研插件——真正倾向是「能复用的全部复用，但影响核心体验的部分自己掌控」
- 自研 GroundMate / MotionCorrector / Atlas 不是喜欢造轮子，而是希望关键环节按自己逻辑运行、拥有控制权

## 产品思维
- 天然会问：用户为什么需要？解决什么？能否一键/实时/非破坏？哪一步最浪费时间？为什么一定要这样操作？有没有成熟方案？
- 关心实际操作体验，而非商业包装
- 适合角色：Creator / Producer / Game Director / Technical Director / Tool Designer（交叉型）

## 学习方式
- 项目驱动：遇到问题 → 学对应知识 → 马上用；不适合系统性学完再动手
- 没有项目牵引时，纯学习会被判定为低效（需要目标牵引）

## 游戏偏好（研究型玩家）
- 玩过/关注：只狼、鬼泣5、仁王2、巫师3、艾尔登法环、黑神话·悟空、猎天使魔女系列、Astral Chain、怪物猎人、忍者龙剑传等
- 研究点：动作系统、角色动作、动画衔接、游戏反馈、镜头设计——玩游戏本质上也在研究游戏
- 天然偏爱：角色 → 动作 → 战斗 → 镜头 → 打击感 → 动画；卡牌 / 模拟经营 / 纯文字叙事方向不成立

## 决策风格
- 发散探索 → 快速淘汰 → 集中深入执行
- 「鱼火」是典型：方向确认后立刻进入「沿这个方向继续给」，不是优柔寡断，是阶段切换

## 性格与风险
- 不追求稳定，愿承担风险，希望拥有自己的项目/IP/工作室/技术/产品/作品（资产归属感重要）
- 最大短板：战线过多、注意力分散（游戏原型、剧情、UE、Maya、插件、Atlas、名字、设计、硬件、手柄、公司、落户、房子、工具并行）
- 对低质量输出迅速失去耐心；能接受「这里我判断错了」，不能接受「没理解却继续自说自话」

## 优势与最终形态
- 优势：能把艺术、技术、产品三个世界连接（视觉审美 + 动画专业 + 技术工具 + 游戏理解 + 产品意识），视觉 + 技术 + 产品交叉型
- 最终形态：独立游戏制作人 / Creative Director + Technical Director；决定游戏长什么样、怎么做、为什么这么做，并亲自解决关键技术问题
- 天然优势区：角色、动作、动画、战斗表现、制作流程——动作表现最可能建立差异化，最可能成为工作室标签

## 核心结论
- 最大课题不是能力不够，而是把动画、技术、审美、游戏理解、叙事、产品思维压缩到一个真正完成的作品上
- 走通后身份变化：一个很会做动画的人 → 一个能够创造完整游戏作品的人
- 一条主线贯穿所有选择：把「脑子里认为应该存在的东西」变成现实——先是动画，再是工具（Atlas），再是游戏，最后是工作室 / IP
