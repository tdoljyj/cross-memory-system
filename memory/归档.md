## 「经常没推到远端」根因实锤：WorkBuddy Bash 沙盒 overlay 覆盖 ~/.workbuddy（2026-08-15）

- 症状：WorkBuddy 侧记忆同步"经常没推到远端"——commit 后远端收不到 / push 状态不可信，反复出现
- 实测（WorkBuddy Bash 沙盒内、三个路径对照）：
  - 写 `~/.workbuddy/__test__.txt` → 下一条命令读取**失败**（overlay 跨命令丢文件）

- 根因：WorkBuddy Bash 沙盒对 ~/.workbuddy 下写入有 overlay、跨命令不持久；记忆同步克隆恰在 `~/.workbuddy/codex-memory-system`，其 .git 写（objects/refs）受 overlay 影响 → commit 落不了盘 / push 状态不可信 → 远端收不到；Codex 克隆在 ~/.codex 不受影响，故 Codex 侧同步一直可靠
- **幻影 ahead 的完整机制（packed-refs stale 条目）**：WorkBuddy 克隆 `.git/packed-refs` 中残留旧的 `48085d5 refs/remotes/origin/main`（18:49 一次 pack-refs 留下）；此后 fetch/pull 尝试写 loose ref `refs/remotes/origin/main`（两层目录）静默失败（exit=0 但不写文件）时，git 自动回落到 packed-refs 里的旧值 → `status` 显示 ahead N 幻影，与真实远端无关；push 是否成功也无从判断。已清除 packed-refs stale 条目 + 手动写回 loose ref = eedc49a，status 恢复 `## main...origin/main`
- **非沙盒判据**：执行带 `dangerouslyDisableSandbox=true` 的 Bash 命令时，输出末尾出现 `⚠️ Sandbox bypassed (escalation-approved)` 才是真正非沙盒、写入真实落盘；没有该提示则仍在沙盒 overlay 里，写入跨命令不持久。对照实测：同一条命令内 mkdir / update-ref 在"伪非沙盒"下失败（目录消失）、在真非沙盒下全部成功
- 处理：两个克隆的 AGENTS.md 均补充「执行纪律」——git 写操作在带沙盒 overlay 的环境必须非沙盒执行（系统 PowerShell / 编辑器文件通道 / 批准沙盒放行）；push 后用 `git ls-remote origin` 对比远端真实 commit 确认已推送，勿依赖 status 的 ahead 显示
