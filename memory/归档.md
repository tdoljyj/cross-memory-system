## tracking ref 写入缺陷：完整排查与根因实锤（2026-08-15 ~ 08-16）

### 症状与误归因演进
- 最早 2026-08-15 误归因「PortableGit 两层 loose ref 写入缺陷」：`git fetch` 显示更新 origin/main 成功但引用永不持久化，status 幻影 ahead/gone，`update-ref` 返回 0 但不写文件；一层目录 ref 正常、两层及以上失败，对象传输不受影响（此归因已被 00:35 推翻）
- 幻影 ahead 机制：`.git/packed-refs` 残留旧 tracking ref（一次 pack-refs 留下）；fetch/pull 写 loose ref `refs/remotes/origin/main`（两层目录）静默失败（exit 0 不写文件）时 git 自动回落 packed-refs 旧值 → status 显示 ahead N 幻影，与真实远端无关
- 沙盒 overlay 首次实锤（三路径对照）：写 `~/.workbuddy/__test__.txt` 跨命令读取失败；写 `~/.codex`、`~/Documents` 跨命令读取成功 → 沙盒对 ~/.workbuddy 下写入有 overlay、跨命令不持久；记忆克隆恰在 `~/.workbuddy/codex-memory-system`，故 .git 写受影响，Codex 克隆（~/.codex）不受影响

### 根因实锤（00:35，推翻 PortableGit 归因）
- Chase 追问根治，GIT_TRACE2 cmd_ancestry 决定性证据：Bash/PowerShell 通道的 git 都被 `sandbox-cli.exe` 包裹（`git.exe <- bash.exe/powershell.exe <- sandbox-cli.exe <- WorkBuddy.exe`）→ 写入走沙盒 overlay
- 排除项（全部实测复现失败）：git 版本（官方 Git for Windows 2.55.0.3 + 2.54.0.windows.1 便携版 + PortableGit 2.55.0.windows.3 三来源）、仓库损坏（全新仓库 init 同样失败）、shell 环境（Bash + PowerShell 都失败）→ 锁定沙盒 overlay 拦截
- 机制：沙盒拦的是 git 写 ref 的 lockfile+rename 原子写；两层子目录 ref 写不进且 exit 0 静默失败（还会清空父目录）；单层 ref 正常；Python `os.makedirs+open` 直写两层目录成功（不走 rename）→ 故「Python 直写 ref」一直是可靠止血
- 数据零风险：fetch/push/commit 对象传输全程正常，只有 tracking ref（状态显示指针）写不进；status 的 ahead/behind/gone 均不可信，一切以 ls-remote 为准
- dangerouslyDisableSandbox 触发不稳定：删除/推送类「危险」操作弹批准真 bypass（输出尾 `⚠️ Sandbox bypassed`），git 读写类常不触发仍在沙盒 → 时好时坏
